Non-interactive headless run. Build TODAY's edition of the "India VC, simply" site,
then commit and push so it publishes. Be concise.

Context: landing index.html + fixed edition-template.html + one folder per day
editions/YYYY-MM-DD/ (data.js, index.html copied from the template, poster.png) +
archive editions.js. Design and data are separate — you only add a new dated edition
and one line to editions.js. Keep all copy very simple / ELI5, with a short "why it
matters" where it helps. Figures are approximate.

FRESHNESS (do this FIRST):
- Read the data.js of the 3 most recent editions/*/ folders (by date).
- Note their bigIdea.title, every deals[].co, every trends[].h, every
  chartsOfTheDay[].headline (topic, not just wording), and every history.sector.
- Today MUST be different: do NOT reuse the same big idea, the same deals, the same
  trend angles, the same chart-of-the-day topic, or the same backstory sector.
  Prioritise genuinely NEW developments from the last 24-48 hours.
- If a story you covered earlier has moved forward, frame today's mention as an
  explicit update — start it with "Follow-up:" and say what is NEW vs before (a new
  number, a next step, a reaction), not a restatement. Also set continuity.status
  to "developing" and continuity.note to one plain sentence naming what's new.
- If it's a genuinely quiet news day (nothing new enough for a real "big idea"), say
  so honestly: set continuity.status to "quiet" and continuity.note to one sentence
  on the PROGRESS of an already-running story (a number that moved, a step taken) —
  then still make the edition a fresh ANGLE for bigIdea (a deeper explainer on one
  theme, a contrarian take) rather than manufacturing a fake new headline. Never a
  copy of a previous day.
- Otherwise (a genuinely new story), omit continuity entirely.

EDITORIAL QUALITY (bigIdea and chartsOfTheDay especially) — write like a16z's
"Charts of the Week" / trend pieces, not a stat report:
- Name the pattern. Give bigIdea.title (and each chartsOfTheDay.headline) a
  memorable label for the phenomenon, not a flat description. "Funding fell 15%"
  is a stat; "The money got picky" is a named pattern.
- Connect 2-3 forces into one "why now" story instead of reporting one number in
  isolation — e.g. (economic pressure) + (a behavior shift) + (a new enabler)
  converging is more compelling than any one alone.
- Reframe something familiar non-obviously where you can: show how a fact people
  already know (rising costs, a slow quarter) is actually causing or enabling the
  real story, not just background noise.
- Back every claim with a concrete number from your research — never vibes.
- Prefer a forward-looking close (what this sets up next) over a flat summary.

Then build the edition:
1. Web-search the most important Indian VC / startup news from the last 24-48 hours.
2. TODAY = YYYY-MM-DD, LABEL = "D Month YYYY". Create editions/TODAY/.
3. Write editions/TODAY/data.js as window.BRIEF = { ... } with:
   - dateLabel: LABEL
   - stats: 3 x {n,l}
   - charts.weekly: {labels[3], values[3] ($M), cap}
   - charts.rotation: monthly, quarterly, annual — each {labels, values (x vs that
     prior period, baseline 1.0), cap}; pick the 5-8 most relevant sectors per
     window (they may differ).
   - charts.gov: {labels, values (rupees crore), cap} — keep real scheme sizes
     unless news changes them.
   - bigIdea: {title, lead, body, why}   (a fresh angle vs recent editions)
   - history: {sector, intro, eras:[4-5 x {yr,title,body}]} — REQUIRED, every day.
     Replace the generic "how India's startup scene got here" backstory with a
     SECTOR's own India history: 4-5 eras (yr range, short title, one ELI5
     paragraph) tracing how that specific sector got to today in India. Pick
     whichever sector today's deals/bigIdea most center on; if no single sector
     clearly dominates, use the sector of today's single largest deal. Pick a
     DIFFERENT sector than the last 3 editions' history.sector (see FRESHNESS) —
     never omit this key, since omitting it makes the page fall back to the same
     static generic timeline every time, which reads as "no difference" day to
     day.
   - continuity: {status:"developing"|"quiet", note} — OMIT this key entirely on a
     genuinely new-story day; only include it per the FRESHNESS rules above.
   - trends: 3 x {h,p,why}               (not repeats of recent editions)
   - deals: 4-6 x {amt,sub,co,sector,d}  (this week's real, new rounds)
   - investors: 4-8 x {firm,country,focus,deal}
   - chartsOfTheDay: 2-3 x {headline,bullets[2-3],chart:{type:"bar"|"line"|"doughnut",
     labels,values,unit,cap},source} — a16z-tweet-style: a punchy, specific claim as
     the headline (not a neutral label), 2-3 short stat-line bullets, one chart.
     Topics must be BROADER ecosystem/macro context not already covered by
     weekly/rotation/gov/deals elsewhere on the page — e.g. unicorn count over time,
     IPO pipeline, fund dry powder, city-wise funding split, seed→Series A
     conversion, foreign vs domestic LP mix, women-founder share, average round
     size trend. Pick whichever 2-3 are timeliest today, and never the same topic
     as the last 3 editions (see FRESHNESS).
   - deck: {summary, takeaways[3], implications[3]}
   - sources: 5-8 x {t,s,url}  (real, working, recent URLs)
4. Run: python3 check_freshness.py TODAY — a HARD, mechanical check (not just the
   FRESHNESS instructions above) against the last 3 editions' bigIdea.title,
   deals[], trends[], chartsOfTheDay[] headlines, and history.sector. If it exits
   non-zero, fix editions/TODAY/data.js per what it flags and rerun until it passes
   — do not proceed to publishing on a failure.
5. Copy edition-template.html to editions/TODAY/index.html, replacing __OGURL__ with
   https://nebulatris.github.io/editions/TODAY/ and __OGIMAGE__ with that URL +
   poster.png.
6. Prepend {date:TODAY,label:LABEL,url:"editions/TODAY/",headline:<bigIdea.title>}
   to window.EDITIONS in editions.js.
7. Run: python3 poster.py TODAY
   Run: python3 cotd_poster.py TODAY  (renders cotd-1.png, cotd-2.png, ... — one
   shareable poster PNG per chartsOfTheDay item; no-ops safely if that key is empty)
8. node --check the inline JS of editions/TODAY/index.html.
9. Write editions/TODAY/tweet.txt (gitignored): an X caption under 280 chars —
   headline + one-line lead + edition URL + 2-3 hashtags. Print it.
10. Commit all changes with message "Edition: TODAY" (real date) and push to main.
    Print the commit hash and https://nebulatris.github.io/editions/TODAY/.
